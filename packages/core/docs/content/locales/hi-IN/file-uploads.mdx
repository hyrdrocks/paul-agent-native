# फ़ाइल अपलोड

फ्रेमवर्क एक फ़ाइल अपलोड एब्स्ट्रैक्शन प्रदान करता है जो एक कॉन्फ़िगर करने योग्य प्रदाता के माध्यम से अपलोड को रूट करता है। टेम्प्लेट `uploadFile()` को कॉल करते हैं और एक URL वापस प्राप्त करते हैं - स्टोरेज बैकएंड एप्लिकेशन कोड को बदले बिना स्वैप किया जा सकता है।

## यह कैसे काम करता है {#how-it-works}

अपलोड अनुरोध `POST /_agent-native/file-upload` पर जाते हैं, जो सक्रिय प्रदाता को भेजता है। आप जाँच सकते हैं कि कौन सा प्रदाता `GET /_agent-native/file-upload/status` पर कॉन्फ़िगर किया गया है।

प्रदाता समाधान आदेश है:

1. **उपयोगकर्ता-पंजीकृत प्रदाता** — `registerFileUploadProvider()` के माध्यम से पंजीकृत कस्टम प्रदाता
2. **Builder.io प्रदाता** - अंतर्निहित, Builder.io कनेक्ट होने पर स्वचालित रूप से सक्रिय हो जाता है
3. **SQL फ़ॉलबैक** — डेटाबेस में फ़ाइलों को बेस64 के रूप में संग्रहीत करता है, केवल वहीं जहाँ होस्ट इसकी अनुमति देता है (स्थानीय विकास; Workers पर, स्थायी डेटाबेस के साथ, या उत्पादन में कभी नहीं)

## डिफ़ॉल्ट: SQL फ़ॉलबैक {#sql-fallback}

जब कोई प्रदाता कॉन्फ़िगर नहीं होता, तो पेलोड कहीं और संग्रहीत किया जा सकता है या नहीं — यह **होस्ट** तय करता है, कॉल करने वाला कोड नहीं। स्थानीय डेटाबेस के विरुद्ध स्थानीय रन फ़ाइल को संसाधन प्रणाली के माध्यम से SQL में base64 के रूप में संग्रहीत करता है और एक बार की चेतावनी लॉग करता है — यह विकास की सुविधा है, उत्पादन मोड नहीं।

बाकी हर जगह अपलोड बंद रूप में विफल होता है। Cloudflare Workers पर, स्थायी `DATABASE_URL` के साथ, या `NODE_ENV=production` के साथ, `uploadFile()` एक `FileUploadStorageNotConfiguredError` फेंकता है जिसका `.setup` बताता है कि क्या कॉन्फ़िगर करना है। यह कभी ऐसा मान नहीं लौटाता जिसे कॉल करने वाला संग्रहीत फ़ाइल समझ ले।

कोई होस्ट एक नीति पंजीकृत करके अपनी नीति घोषित करता है:

```ts
import { registerFallbackStoragePolicy } from "@agent-native/core/hosts";

registerFallbackStoragePolicy({
  id: "my-host",
  priority: 30,
  decide() {
    if (!runningOnMyHost()) return null; // यह होस्ट नहीं
    return {
      permitted: false,
      policy: "my-host",
      reason: "This app runs on a host with no store for a file body.",
      setup: "Bind an object store and set MY_HOST_BUCKET.",
    };
  },
});
```

## Builder.io होस्टिंग {#builder-hosting}

जब आपका ऐप Builder.io से कनेक्ट होता है, तो फ़ाइल अपलोड स्वचालित रूप से Builder की एसेट होस्टिंग पर रूट हो जाते हैं। फ़ाइलों को CDN से बिना किसी कॉन्फ़िगरेशन की आवश्यकता के परोसा जाता है। यह अनुशंसित उत्पादन सेटअप है.

## कस्टम प्रदाता {#custom-providers}

किसी भी स्टोरेज बैकएंड (S3, Cloudflare R2, GCS, आदि) का उपयोग करने के लिए सर्वर प्लगइन में एक कस्टम प्रदाता पंजीकृत करें:

```ts
// server/plugins/file-upload.ts
import { registerFileUploadProvider } from "@agent-native/core/file-upload";

export default defineNitroPlugin(() => {
  registerFileUploadProvider({
    id: "s3",
    name: "Amazon S3",
    isConfigured: () => !!process.env.S3_BUCKET,
    upload: async ({ data, filename, mimeType }) => {
      const key = `uploads/${Date.now()}-${filename}`;
      await s3Client.putObject({
        Bucket: process.env.S3_BUCKET!,
        Key: key,
        Body: data,
        ContentType: mimeType,
      });
      return {
        url: `https://${process.env.S3_BUCKET}.s3.amazonaws.com/${key}`,
        provider: "s3",
      };
    },
  });
});
```

## API अपलोड करें {#upload-api}

`FileUploadProvider` इंटरफ़ेस:

```ts
interface FileUploadProvider {
  id: string; // Unique id, e.g. "s3"
  name: string; // Human-readable name
  isConfigured: () => boolean; // True when ready (env vars set, etc.)
  upload: (input: FileUploadInput) => Promise<FileUploadResult>;
}

interface FileUploadInput {
  data: Uint8Array | Buffer; // File contents
  filename?: string; // Original filename
  mimeType?: string; // MIME type, e.g. "image/png"
  ownerEmail?: string; // For per-user scoping in fallback
}

interface FileUploadResult {
  url: string; // Public URL for the uploaded file
  id?: string; // Provider-specific id
  provider: string; // Which provider handled it
}
```

actions या सर्वर कोड में `@agent-native/core/file-upload` से `uploadFile()` का उपयोग करें:

```ts
import { uploadFile } from "@agent-native/core/file-upload";

const result = await uploadFile({
  data: fileBuffer,
  filename: "photo.jpg",
  mimeType: "image/jpeg",
});

if (result) {
  // Provider handled it — result.url is the public URL
} else {
  // कोई प्रदाता कॉन्फ़िगर नहीं है और यह होस्ट स्थानीय फ़ॉलबैक की अनुमति देता है।
  // बाकी हर जगह इसके बजाय FileUploadStorageNotConfiguredError फेंका जाता है।
}
```

`uploadFile()` ठीक एक स्थिति में `null` लौटाता है — कोई प्रदाता कॉन्फ़िगर नहीं है और होस्ट फ़ॉलबैक की अनुमति देता है। बाकी दो स्थितियाँ टाइप किए गए थ्रो हैं, इसलिए उन्हें कभी संग्रहीत फ़ाइल समझा नहीं जा सकता:

| फेंका गया | अर्थ | मरम्मत |
| --- | --- | --- |
| `FileUploadStorageNotConfiguredError` | कोई स्टोर नहीं, और यह होस्ट फ़ॉलबैक से इनकार करता है। | `.setup` पढ़ें। |
| `FileUploadProviderUnreadableError` | स्टोर कॉन्फ़िगर है या नहीं, यह पढ़ा नहीं जा सका। | क्रेडेंशियल स्टोर ठीक करें; यह सेटअप की गलती नहीं है। |
