# Téléchargements de fichiers

Le framework fournit une abstraction de téléchargement de fichiers qui achemine les téléchargements via un fournisseur configurable. Les modèles appellent `uploadFile()` et récupèrent un URL : le backend de stockage est échangeable sans modifier le code de l'application.

## Comment ça marche {#how-it-works}

Les requêtes de téléchargement sont envoyées à `POST /_agent-native/file-upload`, qui les envoie au fournisseur actif. Vous pouvez vérifier quel fournisseur est configuré sur `GET /_agent-native/file-upload/status`.

L'ordre de résolution du fournisseur est :

1. **Fournisseurs enregistrés par l'utilisateur** : fournisseurs personnalisés enregistrés via `registerFileUploadProvider()`
2. **Fournisseur Builder.io** — intégré, s'active automatiquement lorsque Builder.io est connecté
3. **secours SQL** — stocke les fichiers en base64 dans la base de données, uniquement là où l'hôte l'autorise (développement local ; jamais sur Workers, avec une base de données persistante, ni en production)

## Par défaut : Retour SQL {#sql-fallback}

Lorsqu'aucun fournisseur n'est configuré, c'est l'**hôte** qui décide si la charge utile peut être stockée ailleurs, et non le code appelant. Une exécution locale sur une base de données locale stocke le fichier en base64 dans SQL via le système de ressources et enregistre un avertissement unique : c'est une commodité de développement, pas un mode de production.

Partout ailleurs, l'envoi échoue de manière fermée. Sur Cloudflare Workers, avec une `DATABASE_URL` persistante ou avec `NODE_ENV=production`, `uploadFile()` lève `FileUploadStorageNotConfiguredError`, dont le champ `.setup` nomme ce qu'il faut configurer. Elle ne renvoie jamais une valeur que l'appelant pourrait confondre avec un fichier stocké.

Un hôte déclare sa propre politique en en enregistrant une :

```ts
import { registerFallbackStoragePolicy } from "@agent-native/core/hosts";

registerFallbackStoragePolicy({
  id: "my-host",
  priority: 30,
  decide() {
    if (!runningOnMyHost()) return null; // pas cet hôte
    return {
      permitted: false,
      policy: "my-host",
      reason: "This app runs on a host with no store for a file body.",
      setup: "Bind an object store and set MY_HOST_BUCKET.",
    };
  },
});
```

## Hébergement Builder.io {#builder-hosting}

Lorsque votre application est connectée à Builder.io (offre gratuite disponible), les téléchargements de fichiers sont automatiquement acheminés vers l'hébergement d'actifs de Builder. Les fichiers sont servis à partir d'un CDN sans aucune configuration nécessaire. Il s'agit de la configuration de production recommandée.

## Fournisseurs personnalisés {#custom-providers}

Enregistrez un fournisseur personnalisé dans un plugin de serveur pour utiliser n'importe quel backend de stockage (S3, Cloudflare R2, GCS, etc.) :

```ts
// server/plugins/file-upload.ts
import { registerFileUploadProvider } from "@agent-native/core/file-upload";

export default defineNitroPlugin(() => {
  registerFileUploadProvider({
    id: "s3",
    name: "Amazon S3",
    isConfigured: () => !!process.env.S3_BUCKET,
    upload: async ({ data, filename, mimeType }) => {
      const key = `uploads/${Date.now()}-${filename}`;
      await s3Client.putObject({
        Bucket: process.env.S3_BUCKET!,
        Key: key,
        Body: data,
        ContentType: mimeType,
      });
      return {
        url: `https://${process.env.S3_BUCKET}.s3.amazonaws.com/${key}`,
        provider: "s3",
      };
    },
  });
});
```

## Télécharger API {#upload-api}

L'interface `FileUploadProvider` :

```ts
interface FileUploadProvider {
  id: string; // Unique id, e.g. "s3"
  name: string; // Human-readable name
  isConfigured: () => boolean; // True when ready (env vars set, etc.)
  upload: (input: FileUploadInput) => Promise<FileUploadResult>;
}

interface FileUploadInput {
  data: Uint8Array | Buffer; // File contents
  filename?: string; // Original filename
  mimeType?: string; // MIME type, e.g. "image/png"
  ownerEmail?: string; // For per-user scoping in fallback
}

interface FileUploadResult {
  url: string; // Public URL for the uploaded file
  id?: string; // Provider-specific id
  provider: string; // Which provider handled it
}
```

Utilisez `uploadFile()` à partir de `@agent-native/core/file-upload` dans actions ou le code serveur :

```ts
import { uploadFile } from "@agent-native/core/file-upload";

const result = await uploadFile({
  data: fileBuffer,
  filename: "photo.jpg",
  mimeType: "image/jpeg",
});

if (result) {
  // Provider handled it — result.url is the public URL
} else {
  // Aucun fournisseur configuré ET cet hôte autorise un repli local.
  // Partout ailleurs, FileUploadStorageNotConfiguredError est levée à la place.
}
```

`uploadFile()` renvoie `null` pour exactement une condition : aucun fournisseur configuré et l'hôte autorise un repli. Les deux autres conditions sont des exceptions typées, donc elles ne peuvent jamais être confondues avec un fichier stocké :

| Levée | Signifie | Réparation |
| --- | --- | --- |
| `FileUploadStorageNotConfiguredError` | Aucun stockage, et cet hôte refuse un repli. | Lisez `.setup`. |
| `FileUploadProviderUnreadableError` | Impossible de lire si un stockage est configuré. | Réparez le magasin d'identifiants ; ce n'est pas une erreur de configuration. |
