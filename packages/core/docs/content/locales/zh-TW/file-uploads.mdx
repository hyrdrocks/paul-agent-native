# 檔案上傳

此框架提供了一個檔案上傳抽象，可透過可設定的提供者路由上傳。範本呼叫 `uploadFile()` 並傳回 URL — 儲存後端可交換，無需更改應用程式的程式碼。

## 它是如何工作的 {#how-it-works}

上傳請求傳送至 `POST /_agent-native/file-upload`，後者分派至活動提供者。您可以在`GET /_agent-native/file-upload/status`處檢視設定了哪個提供者。

提供者解析順序是：

1. **使用者註冊的提供者** — 透過 `registerFileUploadProvider()` 註冊的自訂提供者
2. **Builder.io 提供者** — 內建，連線 Builder.io 時自動啟用
3. **SQL 後備** - 僅在主機允許的環境下，將檔案作為 base64 儲存在資料庫中（本機開發；在 Workers 上、使用持久化資料庫或在正式環境中絕不會）

## 預設：SQL 後備 {#sql-fallback}

當沒有設定提供者時，是否允許把負載存到別處由**主機**決定，而不是由呼叫端程式碼決定。針對本機資料庫的本機執行會透過資源系統把檔案以 base64 存入 SQL，並記錄一次性警告——這是開發便利，不是正式環境模式。

在其他任何環境下，上傳都會失敗關閉。在 Cloudflare Workers 上、針對持久化的 `DATABASE_URL`，或在 `NODE_ENV=production` 下，`uploadFile()` 會擲出 `FileUploadStorageNotConfiguredError`，其 `.setup` 欄位指明需要設定什麼。它絕不會回傳一個可能被呼叫端誤認為「檔案已儲存」的值。

主機透過註冊一條策略來宣告自己的策略：

```ts
import { registerFallbackStoragePolicy } from "@agent-native/core/hosts";

registerFallbackStoragePolicy({
  id: "my-host",
  priority: 30,
  decide() {
    if (!runningOnMyHost()) return null; // 不是該主機
    return {
      permitted: false,
      policy: "my-host",
      reason: "This app runs on a host with no store for a file body.",
      setup: "Bind an object store and set MY_HOST_BUCKET.",
    };
  },
});
```

## Builder.io 託管 {#builder-hosting}

當您的應用連線到 Builder.io 時（提供免費方案），檔案上傳會自動路由到 Builder 的資產託管。檔案由 CDN 提供，無需設定。這是推薦的正式環境設定。

## 自訂提供者 {#custom-providers}

在伺服器外掛中註冊自訂提供者以使用任何儲存後端（S3、Cloudflare R2、GCS 等）：

```ts
// server/plugins/file-upload.ts
import { registerFileUploadProvider } from "@agent-native/core/file-upload";

export default defineNitroPlugin(() => {
  registerFileUploadProvider({
    id: "s3",
    name: "Amazon S3",
    isConfigured: () => !!process.env.S3_BUCKET,
    upload: async ({ data, filename, mimeType }) => {
      const key = `uploads/${Date.now()}-${filename}`;
      await s3Client.putObject({
        Bucket: process.env.S3_BUCKET!,
        Key: key,
        Body: data,
        ContentType: mimeType,
      });
      return {
        url: `https://${process.env.S3_BUCKET}.s3.amazonaws.com/${key}`,
        provider: "s3",
      };
    },
  });
});
```

## 上傳 API {#upload-api}

`FileUploadProvider`介面：

```ts
interface FileUploadProvider {
  id: string; // Unique id, e.g. "s3"
  name: string; // Human-readable name
  isConfigured: () => boolean; // True when ready (env vars set, etc.)
  upload: (input: FileUploadInput) => Promise<FileUploadResult>;
}

interface FileUploadInput {
  data: Uint8Array | Buffer; // File contents
  filename?: string; // Original filename
  mimeType?: string; // MIME type, e.g. "image/png"
  ownerEmail?: string; // For per-user scoping in fallback
}

interface FileUploadResult {
  url: string; // Public URL for the uploaded file
  id?: string; // Provider-specific id
  provider: string; // Which provider handled it
}
```

在 actions 或伺服器程式碼中使用 `@agent-native/core/file-upload` 中的 `uploadFile()`：

```ts
import { uploadFile } from "@agent-native/core/file-upload";

const result = await uploadFile({
  data: fileBuffer,
  filename: "photo.jpg",
  mimeType: "image/jpeg",
});

if (result) {
  // Provider handled it — result.url is the public URL
} else {
  // 沒有設定提供者，且該主機允許本機後備。
  // 在其他環境下，這裡會改為擲出 FileUploadStorageNotConfiguredError。
}
```

`uploadFile()` 只在一種情況下回傳 `null` —— 沒有設定提供者，且主機允許後備。另外兩種情況是帶型別的擲出，因此絕不會被誤認為「檔案已儲存」：

| 擲出                                  | 含義                         | 修復                           |
| ------------------------------------- | ---------------------------- | ------------------------------ |
| `FileUploadStorageNotConfiguredError` | 沒有儲存，且該主機拒絕後備。 | 閱讀 `.setup`。                |
| `FileUploadProviderUnreadableError`   | 無法讀出是否設定了儲存。     | 修復憑證儲存；這不是設定錯誤。 |
